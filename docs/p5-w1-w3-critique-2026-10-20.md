## Risks

1. **No Night filter in this MPVKit build (blocks D3's Night).** The device `Libavfilter.framework` (MPVKit `0.41.0-n8.1.2`) holds 13 audio filters: `aformat amix anull aresample areverse asetrate atempo atrim equalizer firequalizer pan superequalizer volume`. There is no `dynaudnorm`, `loudnorm`, `acompressor`, `compand`, `alimiter` or `speechnorm` (checked with `nm` on `iosApp/build/DerivedDataDevice/Build/Products/Debug-appletvos/Libavfilter.framework/Libavfilter`). mpv's own filters in `Libmpv` are `format`, `lavcac3enc`, `scaletempo`, `scaletempo2`. `af=lavfi=[dynaudnorm]` would fail at filter init. See Q1.
2. **No limiter either**, so Boost above 0 dB clips on loud passages. The device pass item "Boost +6 dB audibly louder with no clipping" cannot be guaranteed by code. Keep the 0 to 10 dB range and let the pass decide whether to cap it at 6.
3. **Dialogue pan on the wrong layout.** `pan` with a named output layout fails when the input lacks the named channels (a stereo track after a track switch). Spec B builds the filter from `audio-params/channels` and re-applies it on `MPV_EVENT_AUDIO_RECONFIG`, with a layout-free `equalizer` for anything not in the allowlist.
4. **UI leg `PlayerTopPanelProbeTests` step 4** counts audio rows with `identifier BEGINSWITH 'player.panel.audio.'` (`NuvioTVUITests/PlayerTopPanelProbeTests.swift:61`). New Audio-tab rows must use the `player.panel.audioFx.` prefix or the leg counts them as tracks.
5. **UI leg `testNativePlaybackTabSpeed`** asserts 1× is ticked on open (`NativePlayerParityUITests.swift:159`). A remembered speed for `smoke-mpv` left by a new leg would break it. Spec B limits speed memory to series contexts (the smoke context is a movie unless the new knob is set) and the new leg turns Remember off at the end.
6. **`SubtitleDelayProbeTests`** reaches the Timing row with two Downs (`:85-89`). The Sync Line row goes BELOW the delay row, and is hidden in that leg (no external subtitle), so the leg is unaffected.
7. **Settings description registry**: see Q2.
8. **Localization**: one catalog, five locales. Keys only come into the catalog after a build plus the populate script; `vi` and non-matching keys need translation by hand or MT. The main session owns this after each wave.
9. **Sync Line mpv fetch**: a one-shot or slow add-on URL. 10 s timeout; on failure the list shows "Unable to load subtitle lines". Text encodings: try UTF-8, then ISO Latin-1.
10. **SwiftUI focus in the Sync Line list**: the list replaces the Subtitles tab content inline (Menu closes the whole panel, so a nested sheet is not an option). Focus must be placed on the anchor cue after the list appears, and back on the Sync Line row on Cancel, with the 0.35 s pattern `NativePlaybackTab` uses (`:79-83`). tvOS 27 sim never reports `hasFocus`; legs assert existence and values.
11. **Native end-of-item vs Up Next**: the post-play cover must use the same gate as mpv (`upNext.phase == .hidden`), or the up-next hand-off and the cover race.
12. **Post-play navigation**: pushing while covers dismiss is the "empty-pushed-view EJECT" class. Spec C pushes only from the presenter's cover `onDismiss`.
13. **Native speed restore**: `NativeSpeedModel.apply` before `readyToPlay` sets `defaultRate`; `AVPlayer.play()` starts at `defaultRate` (tvOS 16+). If the device shows otherwise, re-apply at `readyToPlay`.
14. **N1 vs the ±10 s audio-delay row**: the Audio Delay row clamps at `limit: 10` (`MPVPlaybackTab.swift:61`) and the store clamps saves to ±10 s (`apple.kt:99-102`). A 30 s stream hint would display as 30 s and jump to 10 s on the first "+". Spec B raises the row limit to 60 only while a hint is active.

## Spec A: Sync Line (B19)

Self-contained. Branch `claude/player-p5-a` in a clone `~/Claude/Projects/NuvioMobile-p5-a` of `claude/player-p5` (never a worktree; MPVKit is a symlink, stage by explicit paths, never `git add -A`). Read `CLAUDE.md` in the outer repo for the gates. Agent B is editing some of the same files in parallel and lands first; see the end of this spec.

### What it does

A "Sync Line" action in the player's Subtitles tab, under the Timing row, on both engines, only while an external (add-on or stream sidecar) subtitle is selected. Press it while a line is being spoken: the app captures the playback position, loads the subtitle's cues and lists the lines around it. Select the line you just heard: the subtitle delay becomes `captured − cue.start − 300 ms`, clamped to ±60 s, through the existing Timing path (so it persists per episode like the ±0.1 s chips).

### Shared Kotlin

New file `shared/src/commonMain/kotlin/com/nuvio/app/features/player/SubtitleSyncLine.kt`:

```kotlin
package com.nuvio.app.features.player

object SubtitleSyncLine {
    const val WINDOW_BEFORE_MS = 30_000L
    const val WINDOW_AFTER_MS = 10_000L
    const val MAX_ROWS = 30

    /** The delay that puts [cueStartMs] at [capturedPositionMs] minus the reaction time. */
    fun delayMs(capturedPositionMs: Long, cueStartMs: Long): Int =
        (capturedPositionMs - cueStartMs - SUBTITLE_AUTO_SYNC_REACTION_COMPENSATION_MS)
            .coerceIn(SUBTITLE_DELAY_MIN_MS.toLong(), SUBTITLE_DELAY_MAX_MS.toLong())
            .toInt()

    /** The raw cue time the subtitles are showing now: position minus the current delay. */
    fun shownCueTimeMs(capturedPositionMs: Long, currentDelayMs: Int): Long =
        capturedPositionMs - currentDelayMs

    /** Cues sorted by start, whose start is within [shown − 30 s, shown + 10 s], at most 30 (the last 30 when more). */
    fun window(cues: List<SubtitleSyncCue>, capturedPositionMs: Long, currentDelayMs: Int): List<SubtitleSyncCue>

    /** Index in [windowed] of the last cue starting at or before the shown time; 0 when none; null when empty. */
    fun anchorIndex(windowed: List<SubtitleSyncCue>, capturedPositionMs: Long, currentDelayMs: Int): Int?
}
```

Cue times in the list are the RAW file times (the parser reads the unshifted file), which is why the formula ignores the current delay.
