## P1

**1. The 2 MB bounded range is neither what the wire carries nor closed between frames** (`KeyframeThumbnailer.swift:99-103`, `:219-220`, `:528-537`; `ThumbScheduler.swift:342`).
`request_size` bounds each HTTP request to 2 MB, but the thumbnailer reads only up to the key packet (32 KB per frame on the fixture, 0.5–3 MB at 4K) and leaves the rest of that response on the socket. The host keeps sending until the client's receive window fills, so the wire carries anywhere from the read size up to 2 MB per frame, while `bytesRead` (`AVIOContext.bytes_read`) counts only what avio consumed. The half-read response also keeps the connection open, stalled on a zero window, until the next seek closes it. After the pre-warm stops on its budget (`prewarmStopped`, which does not close the thumbnailer, `MPVPlayerView.swift:2029`) or while the player sits under the post-play card, that connection stays open for the rest of playback. Failure scenario on the device pass: a 1080p debrid link where keyframes are 100 KB. The budget logs "40 MB read" while the CDN sent up to 20 times that, and the host sees two connections on the link the whole time, which is exactly what C6 set out to prevent (mpv reconnecting after a long pause and being refused). The A2 record's range-server check logged request ranges, not bytes sent or connection lifetime, so it cannot tell. Fix: (a) set `initial_request_size` (the bundled avformat has it, per C6) to 256–512 KB, so the first range after each seek is small. Most keyframes fit, and with `Connection: close` the server finishes its send and closes. (b) Charge the budget conservatively: `max(bytes_read delta, initial_request_size)` per seek, plus each further `request_size` the read crossed. (c) Close the thumbnailer when the pre-warm stops and no scrub is pending, and reopen lazily with the cached index. Then have the range server log bytes written and connection close time per request, and record both for one 4K frame.

## P2

**2. Index priming has no byte bound** (`KeyframeThumbnailer.swift:290-300`).
`av_seek_frame(ctx, -1, duration, BACKWARD)` on matroska resets to the last known index entry and parses clusters forward while the search keeps returning the last entry. Each parsed video keyframe appends an index entry, so the search keeps finding the newest one and the loop runs to EOF. With full Cues that is the tail after the last cue (the fixture's 452 KB). On an MKV without Cues it is a linear read of the file from the start, stopped only by the 10 s open deadline. Scenario: a Cue-less 1.5 GB 1080p WEB-DL on a fast CDN. The open downloads about 300 MB in 10 s while mpv plays, the interrupted scan leaves about 700 index entries covering the first 20 % (enough to pass the count check), the budget is spent at once, and every slot past 24 minutes snaps to the last entry. Fix: give `ThumbInterruptGate` a byte ceiling (read `pb.bytes_read` in the callback, or arm a 2 s deadline just for priming) of about 16 MB for the priming seek. Require the primed index to span the file (last entry ≥ 0.8 × duration) as well as reach the count; otherwise `.refused(.noIndex)`.

**3. The I-frame trim assumes the first sample starts at the mdat payload** (`IFrameFragment.swift:74`, `:93-95`).
`firstSample` copies bytes from `moofSize + 8` and rewrites `data_offset` to `newMoofSize + 8`, but never checks that the original `data_offset` was `moofSize + 8`. movenc writes it that way for the single-track segments today. If the remuxer ever writes a second `traf`, puts a `sidx`/`styp` before the moof (which the `moof` guard rejects, fine), or the trun omits `data_offset` (the data then starts at the moof under `default-base-is-moof`), the fragment would carry the wrong bytes. AVKit would then decode garbage or drop the rendition, and since the native path is on by default (`harvest`), every native user would see it. Fix: when `dataOffsetField` is present, require `be32 == moofSize + 8`; when absent, return nil (404). Add a unit case for each.

**4. Out-of-order snapshots can regress the mirror** (`MPVPlayerView.swift:1943-1966`, `:2089`).
Harvest inserts run as unstructured `Task`s that `await publish(result)`. Decode inserts and `setKeyframeSpacing` publish from separate main-actor tasks. Actor order and main-actor hop order are not tied, so an older snapshot can land after a newer one, and `storeMirror` then lacks a stamp. The scheduler re-decodes that slot (a full seek and range for a `keptExisting`) and the probe's `thumbs=` steps back by one. Fix: add a monotonically increasing `version` to `SeekPreviewSnapshot` (bumped inside the actor on every mutation) and have `applyStoreSnapshot` ignore anything older than the mirror.

## P3

**5. `takePassEnded()` is consumed before the `inFlight` check** (`MPVPlayerView.swift:2026`). If the flag is ever set while a job is in flight, it is cleared and the decoder for that pass is never released. Swap the operands (`thumbs.inFlight == nil, thumbs.takePassEnded()`).

**6. The view leaving does not stop the chain** (`MPVPlayerView.swift:727-738`). `viewDidDisappear` stops the poll timer, but a job completion still calls `driveThumbs()` and runs out the current pass (up to 8 frames), and the thumbnailer (with item 1's open connection) stays open under the post-play card until `deinit`. When `isLeavingPlayer`, call `thumbs.cancel()` and `closeThumbnailer()` there.

**7. HLS and other non-file URLs pay a full open before the container refusal** (`MPVPlayerView.swift:2065-2072`, `KeyframeThumbnailer.swift:241`). An `.m3u8` source makes avformat fetch the playlist and probe the first segment, then refuse `.container`. Skip on a `.m3u8` path or a `mpegurl` content type before opening.

**8. Description number** (`SettingsDescriptions.swift:399`). Pre-warm stops at the budget (≤ 150 MB), but scrubs continue to `budget + 50 MB`, so "up to 150 MB more per title" can be 200 MB. Say "up to 200 MB", or cap the ceiling at 150 MB for files that hit the 150 MB budget. Re-lint after the edit.

**9. `%d` with a Swift `Int`** (`MPVPlayerView.swift:1985`). Works on arm64 by accident; use `%ld` in the key ("last decode %ld ms") so translators and the format checker agree.

**10. Integration fixture is hard-coded and its skips are invisible in the gate count** (`KeyframeThumbnailerTests.swift:9`). The five tests skip via `XCTSkipUnless`, so "1635/0" does not say whether they ran. Read the URL from a `TEST_RUNNER_` variable (default `:8000`), and record the skip count with the gate in the batch record.

**11. `testDecodeScrubIntoUnwatched` margin** (`PlayerTransportUITests.swift:~494`). Measured 1.11 s against a 1.5 s window that includes the open. On a loaded simulator this is the leg most likely to flake; log the open's `took=` on failure, so a slow open can be told apart from a missed scrub.

**12. Native I-frames are now on for every native-engine user** (`NativePlaybackCoordinator.swift:579`). `harvest` is the default and allows I-frames, so the master gains the `EXT-X-I-FRAME-STREAM-INF` line in Release for SDR, HDR10 and DV alike. A rejection costs a failover to mpv (the retry only drops `SUPPLEMENTAL-CODECS`). That is the plan's call, but device item 5 should cover one title of each range, and the release notes should name the Off row as the kill switch.
