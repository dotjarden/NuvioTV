## Findings

### 1. P2: a B17 rebuild can call `play()` on a player that was already stopped or handed to mpv

**Defect.** `finishRebuild` (`NativePlaybackCoordinator.swift:771-810`) runs inside `observeTask` and awaits three times: `await player.seek` (`:777`), then `loadMediaSelectionGroup` for audible and for legible (`:781-782`). It never re-checks cancellation or ownership before `if target.wasPlaying { player.play() }` (`:780`). The only guard, `guard playerItem === item` (`:783`), comes after the `play()`. `stop()` (`:506-536`) cancels `observeTask`, calls `player?.pause()` and nils `player`, but the task still holds the local `player`. The `fallbackMidPlay` path (`:1723`) is the same: a remux failure or the stall watchdog during the rebuild window cancels the task, sets `.failed`, and the screen swaps to mpv.

**Consequence.** If `stop()` or a fallback lands while the corrective seek is in flight (it runs whenever the tag start lands more than 0.5 s off), the seek completes and `play()` restarts the paused AVPlayer. That player is still retained by the task and by the outgoing `AVPlayerViewController`, so up to the 24 s forward buffer plays as ghost audio over mpv's start or after the viewer has left, until both let go. The rebuild window is short, but it is exactly the moment a remux failure or an exit is most likely (a frozen picture).

**Fix.** After each await in `finishRebuild`, add `guard !Task.isCancelled, self.player === player, playerItem === item, phase == .playing else { isRebuildingItem = false; return }`, placed before `play()` and before the group loads. Also clear `isRebuildingItem` on that early return, so `syncAudioSelection` / `checkLateSubtitles` are never left blocked if a path other than `stop()` ever swaps the item.

### 2. P2 (design, Christian's call): a start-watchdog timeout is never remembered against the link

**Defect.** `fromMpvLog(…, watchdogFired: true)` returns `.network` whenever the ring has no HTTP line (`PlaybackFailureClassifier.swift:23-26`, used at `MPVPlayerView.swift:3462-3467`). `.network` has `remembersLink == false`. `applyingPath` turns this into `.offline` only when the path is unsatisfied; a satisfied path keeps `.network`.

**Consequence.** Before P4, a link that accepts the connection but never delivers media (a common dead debrid or CDN link) went into the 8 h rejected-link memory after one watchdog fire. Now it never does. Every auto-play and every Up Next walk tries it first again and spends the full start-watchdog budget on it before failing over. BUG-143 was about network failures that are the viewer's fault. A watchdog fire while the TV is online and other hosts answer is, on the evidence, more often the link's fault. The spec table (§8.4) makes this choice on purpose, so this is flagged as a behaviour regression rather than a code defect.

**Fix (pick one).** (a) Watchdog fired, path satisfied, no network line in the ring → `.unknown` (remembered); `.network` only when the ring shows a network line. (b) Keep `.network` but remember it with a short TTL (for example 30 min) in `RejectedStreamLinks`. Either way, add a classifier test for the "watchdog + satisfied + empty ring" case.

### 3. P3: `testSearchEmissionAfterSourceListIsDropped` passes without the line it covers

`NextEpisodeEngineTests.swift:326-335` calls `engine.cancel()` before `engine.loadSources()`. `cancel()` → `tearDownSearch()` already bumps `searchGeneration` (`NextEpisodeAutoPlay.swift:414`), so the stale callback is dropped even with `loadSources`' own `searchGeneration += 1` (`:312`) deleted. This is the P3 C22 class. **Fix:** capture a search callback, end the search through a path that does NOT bump the generation (or bump it only in `loadSources`), then call `loadSources()` and fire the stale callback. Or assert on the generation value directly in a DEBUG accessor.

### 4. P3: the BUG-129 busy line does not recover by itself, and covers only one of the two races

- When the search ends while the Sources column is visible, `searchEnded()` (`NextEpisodeAutoPlay.swift:652`) clears `sourcesBlockedBySearch`. The column (`PlayerPlaybackColumns.swift`, the `sourcesBlockedBySearch` branch) then falls through to "No alternate sources found yet.", because `loadSources()` only runs in `onAppear`. The viewer is told to re-open the tab, but the copy now claims there are no sources.
- The reverse race is untouched: the column is open (list owns the flow) and the up-next threshold fires `beginSearch()` → `cancelSourceLoad()` (`:591`), which blanks `sources` under the focused row with no busy line (pre-existing; BUG-129's guard only covers "open during search").

Neither path can leave the tab permanently busy: every search exit (`tearDownSearch`, select at `:803`, no-stream at `:837`, `stop`) calls `searchEnded()`. **Fix:** have the column observe `sourcesBlockedBySearch` going false and call `engine.loadSources()` once while it is still mounted; in `beginSearch`, if `sourceListOwnsFlow`, set `sourcesBlockedBySearch = true` so the open column shows the busy line instead of an empty list.

### 5. P3: the mpv log ring is not scoped to the main stream or to the failure

`MPVPlayerView.swift:3691-3694` appends every warn/error line from every mpv module for the whole session. `fromMpvLog` lets an HTTP line win, then a network line. An add-on subtitle fetch that timed out, a TLS warning from an external subtitle host, or a connection reset that mpv recovered from 20 minutes earlier can therefore classify a later decode failure or early end on a dead link as `.network`, which is never remembered. The 16-line cap limits the damage but does not stop it. **Fix:** keep the prefix (already stored) and ignore lines from subtitle-side prefixes (`sub`, `sd`, external-file loads), or stamp each line with uptime and only read lines from the last N seconds before the failure.

### 6. P3: engine-side native failures are classified as link evidence on the forced-native path

`fromNSError(_, origin: .loopback)` maps any loopback URL error to `.noMedia` (`PlaybackFailureClassifier.swift:136`), which is remembered. It is used for "item failed mid-play" (`NativePlaybackCoordinator.swift:1092-1110`), the comment's own example being a seek past the remux frontier that our JIT server fast-503s. `failIfPreplayback("no usable keyframe index")` also lands on `.unknown` (`:1705-1711`). Both are limits of our engine, not of the link. They matter only when `onFallback == nil` (`context.forcedEngine == .native`, the alert's "try the other engine" retry), so the impact is small. **Fix:** mid-play loopback errors → `.local`; "no usable keyframe index" / "no segment map" before start → `.local` as well, keeping `.noMedia` for "no segments produced".

### 7. P3: a chapter seek during a B17 rebuild is undone

`seek(toChapter:)` (`NativePlaybackCoordinator.swift:827-832`) does not check `isRebuildingItem`. During a rebuild, `finishRebuild` then compares the landing with the pre-rebuild `target.positionSec` and seeks back if it is more than 0.5 s off (`:776-778`). A chapter pick in that window is silently reverted. **Fix:** ignore chapter seeks while `isRebuildingItem` (the panel closes on pick anyway), or record the chapter target as the rebuild's new `positionSec`.

### 8. P3: the mpv overlay leg's `.ts` fixture has no checked-in recipe

`mpvFixtureURL()` (`NativePlayerParityUITests.swift:349-354`) derives `test-long.ts` from `PLAYER_SMOKE_URL`. The plan record (`docs/player-revamp-plan-2026-10-06.md:535`) says only "the same file remuxed to MPEG-TS". The 10-04 disk purge already deleted these fixtures once. **Fix:** add the exact command beside the chapters recipe (spec §12), for example `~/bin/ffmpeg -i test-long.mkv -map 0 -c copy -f mpegts test-long.ts` plus a check with `ffprobe`. Better still, have the leg `XCTSkip` with that command in the message when the URL 404s.

### 9. P3: the Loading Screen off-leg restores "on" unconditionally, and the row is a synced setting

`testLoadingOverlayOff` (`NativePlayerParityUITests.swift:426-458`) records `before` but its teardown always sets the row back to on (`:433-438`). If the fixture had it off, the leg leaves it changed. The teardown is registered after `setLoadingScreen` returns, so a failure inside `setLoadingScreen` after the Select press (the `XCTAssertEqual` at `:506`) still returns `before` and is covered. A nil return (row not reached) happens before any press, so nothing leaks there either. The bigger point: `show_loading_overlay` is shared and synced with the phone (`PlayerSettingsRepository.kt:36`). On a signed-in fixture this leg would push "off" to the account for the length of the run. The FA87 fixture is a local guest profile today, which is why this is P3. **Fix:** restore `before`, and skip the leg when the profile is signed in, or note in the leg that it must only run on a guest fixture.

### 10. P3: device-only items the legs cannot prove

- **B16 pause card:** `testNativePauseCard` skips when the simulator's bar never hides while paused (`:244-246`), so the card is proven only on hardware. Keep it on the device-pass list, along with the kill switch `NativePauseCardRule.supported`.
- **Any-press recogniser:** `anyPress` (`PlayerPanelHost.swift:66-78`) is a simultaneous `UITapGestureRecognizer` on Select/Play-Pause/arrows with `cancelsTouchesInView = false`. Its shape matches the proven `downPress`, but a Select tap recogniser is new. On device, check that Select-hold (AVKit scrub / contextual actions) and Play/Pause still behave, and that Menu exits (Menu is correctly left out of the recogniser and only observed in `pressesBegan`).
- **`AVTextStyleRule`:** the rule is always installed (foreground + edge keys always present, `NativeSubtitleStyle.swift:59-66`). On device, check that a viewer's tvOS Settings › Accessibility › Subtitles style with "override" still wins over it.
- **Native subtitle gate 8 s → 3 s (`NativePlaybackCoordinator.swift:549-568`):** in Release, add-ons that answer between 3 and 8 s now take the late path. For a preferred-language DEFAULT rendition with nothing showing, that means an automatic item rebuild (a short picture hold) in the first seconds of playback. Release-note it. Watch `took=` on the `[Subs] late rebuild` line in the device pass.

## Clean (verified)

- **B17 observer lifecycle:** the rebuild cancels the old `observeTask` before installing a new one. `observeMediaSelection` removes the old item's notification observer before adding the new one (`:1219-1227`). The status and stall checks are polled per item inside `observeTask` (no per-item KVO to leak). `timeControlObserver` is per player, so it carries across items correctly. There is no periodic time observer and no `FailedToPlayToEndTime` observer to double-add. Every item (first, signaling retry, rebuild) goes through `decorate()`, so the buffer bound, `textStyleRules`, `externalMetadata` and `navigationMarkerGroups` are on all three. `setMediaSelectionCriteria(nil)` plus the `isRebuildingItem` gate in `syncAudioSelection` stop the new item's initial pick from reaching the worker (C-2). A rebuild that never readies falls back to mpv after 12 s with `.local` (never remembered). A pre-ready rebuild failure goes `.local` → mpv, never the signaling retry.
- **Rebuild vs audio switch / subtitle delay:** audio switches are in-item (server + worker, no item swap), so there is nothing to race. The delay apply/refetch tasks are cancelled at rebuild start, the server-side delay persists, and the fresh item fetches bodies at the current delay.
- **`LocalHLSServer`:** `_subtitles`, `_subtitleFlags` and `_startOffsetSec` are read under `lock` in every request path (`renderedPlaylist`, `serveSubtitle`, subtitle playlists). `EXT-X-START` is only rendered while set and is cleared in `finishRebuild`. The query string on `?late=1` is ignored by the server.
- **Artwork:** cancelled in `stop()`. It checks `Task.isCancelled` after the detached encode and before touching `playerItem`, and writes only on main. `stop()` also cancels `lateDebounce`. The DEBUG late-subtitle task is weak and guarded on `phase`.
- **`NetworkPathMonitor`:** singleton, started on its own utility queue at `NuvioTVApp.init`, never cancelled. The state sits behind `NSLock`, and it is true until the first update.
- **mpv threading:** `MPVLogRing` is lock-guarded, appended on `eventQueue` and snapshotted on `eventQueue` for END_FILE (in event order) or under the lock on main for the watchdog/early end (no per-line main hop, C8). `screenshot-sw` is written only on `eventQueue`, only on change, and only once `yes` has been written. `current-vo` is read on `eventQueue`. The `PLAYBACK_RESTART` stage hop is a strong `main.async` (BUG-141/C13). The harvest main hop stays strong. `screenshot-raw` and `applyHarvestScreenshotPath` stay under `#if !targetEnvironment(simulator)`. `cache-buffering-state` is registered with the other observers (none of them are unobserved; `mpv_terminate_destroy` owns teardown, as before).
- **Borrowed node bytes:** `screenshotRaw` scales inside the `withCommandResult` read closure, before the deferred `mpv_free_node_contents`. The source `CGImage` and its no-op-release provider are locals. `CGContext(data: nil)` owns the thumbnail's buffer. `autoreleasepool` wraps the whole capture on `eventQueue`. The sentinel arm/clear still brackets the native call (the scale now sits inside it, which is acceptable: a CG crash there also turns the harvest off). The synthetic path defaults to 640×360 when the knob is unset.
- **SDR gate:** `useSoftware` keeps the VO path for `pq`, `hlg`, unknown/`auto`/empty gamma and the `dolbyvision` colour matrix. That covers DV P5 (matrix), DV P8.1 (PQ) and P8.4 (HLG). The format-argument retry is unchanged.
- **`took=`:** it now includes a few milliseconds of scaling. Hardware VO captures were 82–225 ms against `slowHarvestMs = 60`, so the once-per-file backoff (10 → 30 s) already fires and the change does not move it. Only a software-path capture landing at 55–60 ms could tip over, which matters little.
- **mpv startup reducer:** `applyPendingResume` returns the resume seek's generation and `issueSeek` is unchanged, so no seek path loses its restart. A rejected or superseded resume seek is caught by the position-advance backstop. A restart before the resume seek does not count. Mid-play rebuffers show the small spinner only after `playbackStarted`. The overlay is gated on `!playbackStarted`, so it can never sit over a rebuffer, the post-play cover or the up-next chip. It is `allowsHitTesting(false)` and `focusable(false)`.
- **`MPVPlaybackTab` → `PlayerPlaybackColumns`:** a verbatim move. Same actions (`setSpeed`, `jumpToEpisode`, `playSource`), the same `player.panel.speed.*` identifiers (plus a harmless `accessibilityValue`), the same focus sections and widths. The `firstRowFocus` binding is nil on mpv.
- **AVPVC host:** the delegate is set once in `viewDidLoad` (`loadViewIfNeeded` before configuring). The transport-bar callback arrives on main. Closures capture `host` and `panel` weakly. The speed model and engine are held by the container and panel, with no cycle back to the host.
- **Pause card:** `pauseCardTask` is cancelled on resume and in `onDisappear`. "Unknown = visible" holds (`barKnownHidden` is reset on every pause), so a silent delegate can never put the card over the bar.
- **BUG-129:** every search exit calls `searchEnded()`. `jumpToEpisode` tears down then begins a fresh generation. `sourceListOwnsFlow` is set in `loadSources` and cleared in `cancelSourceLoad`/`stop`, so preload suppression and `noteSourceListClosed` key on it the same in live code and tests.
- **BUG-143 walk:** `FirstPlayAutoPlay` still calls `tryNext` for every failed outcome. The resolve timeout no longer rejects. An offline reject is skipped and logged. `StreamPickerView` skips both the remember and the debrid invalidate for non-remembered kinds while the failover still advances. FFERRTAG constants, Darwin errno values and the NSURL/CoreMedia sets are correct.
- **A8/A9/A6:** speed goes through `selectSpeed`, and the live rate follows only while playing (paused, it stays on `defaultRate`). Episodes/Sources menu items appear only with `canSwitchStreams` (Episodes also needs an episode list). The metadata identifiers are right (`commonIdentifierTitle`, `iTunesMetadataTrackSubTitle`, `commonIdentifierDescription`, `commonIdentifierArtwork` as JPEG, `und`). The CMTextMarkup ARGB arrays are 0–1 floats, the size is in percent clamped 65–222, and the edge style is Uniform/None. Signed Android-style ARGB ints decode correctly. Chapter times are mapped onto the first-keyframe origin and trimmed at the end. A chapter seek is an exact AVPlayer seek, which the skip planner reads as a user jump (never auto-skip bait).
- **Strings:** all 29 new user-visible literals are in `Localizable.xcstrings` with de/es/fr/it/vi (`Buffering \(p) %` → `Buffering %lld %%`, `Season %lld · Episode %lld`). The catalog parses as JSON (1456 keys). Both new rows have a `SettingsDescriptionID` and a description, and `SettingsDescriptionsTests` iterates `allCases`. The sampled translations read naturally.

## Release-note facts

**Settings (user-facing):**
- Settings › Playback › **Loading Screen**: new, **on** by default. Shared and synced with the phone app's loading-overlay setting (`show_loading_overlay`), so a phone user who turned it off gets the plain spinner on the TV. Off draws the old spinner.
- Settings › Playback › **Pause Info Card**: existing, **on** by default, now on both players. On the Apple TV player it appears 1.5 s into a pause, once the system bar has hidden.

**Developer (A/B):**
- **Harvest Screenshot Path (A/B)**: **Software for SDR** (default) / Video Renderer. Key `debug.harvestScreenshotSW`, read in every build, applies to the next playback.

**Behaviour changes without a setting:** the Apple TV player shows chapters (Chapters tab plus transport-bar markers); its subtitles follow the app's subtitle style (colour, background, outline on/off, bold, size); the system speed pill offers the same seven speeds as the panel; the transport bar adds Episodes / Sources items; Now Playing gets title, episode line, synopsis and poster; add-on subtitles that arrive late are added mid-play (one item rebuild at most per playback); the add-on subtitle wait before the first frame drops from up to 8 s to 3 s past remux readiness; a failed link is no longer remembered for network, offline, cancelled or our-own-engine failures, nor for a debrid resolve timeout (see finding 2).

**DEBUG knobs (not in release notes):** `-debug.nativeSubsGateSec`, `-debug.nativeLateSubtitleURL` / `-debug.nativeLateSubtitleDelaySec`, `-debug.nativeRebuildStartMode tag|seek|none`, `-debug.mpvSmokeEngine native|mpv`, `-debug.harvestSyntheticSize WxH`, `debug.remuxSmokeChapter`, `debug.remuxSmokeLatePickSec`.
