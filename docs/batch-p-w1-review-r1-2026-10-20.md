## P1

### P1-1. FEAT-82: the fixed square reaches Classic Detail, where it squashes text buttons and stretches Play

`Screens/DetailView.swift:2549-2553` computes `squareSide` with `iconOnly: true` hard-coded, and the result is applied unconditionally:
- `.modifier(DetailActionSquareFrame(side: squareSide))` on Watch Trailer (2293), Mark Watched (2313), Add to Library (2333), Shuffle (2360) and Start Over (2505);
- `.modifier(DetailActionSquareLabel(side: squareSide))` inside `actionButtonPadding`'s icon-only branch (2558), which Play also goes through (`primary: true`).

`usesIconOnlyLabel(primary:)` (2370) is `detailLayout == .cinematic ? !primary : actionIconsOnly`. So with Poster > Corners = Square:
1. **Classic Detail, Icons Only off** (the default for Classic): the secondary buttons draw text labels ("Watch Trailer", "Mark Watched", "Add to Library") and still get `.frame(width: side, height: side)`, about a 60 to 70 pt square. The text is truncated or wrapped inside a square button.
2. **Classic Detail, Icons Only on**: Play is icon-only too, so its label gets `.frame(maxWidth: .infinity, maxHeight: .infinity)` with no fixed outer frame. Play then fills the rest of the action row's width (and any finite height the parent proposes), and because `playButtonHeight` is measured from that Play, the squares follow whatever Play stretched to.

Cinematic is correct (Play is never icon-only there, and every secondary is). The spec's own hunk (critique Spec B, P4 step 3 (c)/(d)) has the same gap: it gated the label branch but not the frame; the main session applied it faithfully. The UI leg (`iosApp/NuvioTVUITests/DetailActionSquareUITests.swift`) only launches `-detail_layout cinematic`, so nothing catches it.

Fix (DetailView.swift, replaces 2547-2553 and the two call shapes):
```swift
/// FEAT-82: the fixed square side for a SECONDARY icon-only button (Corners = Square and Play
/// measured), else nil. Play never takes it (it is the measure), and text labels never do.
private var squareSide: CGFloat? {
    let side = DetailActionSquare.side(playHeight: playButtonHeight)
    return DetailActionSquare.applies(isSquare: DetailActionShape.isSquare(cornerRadius: posterStyle.cornerRadius),
                                      iconOnly: usesIconOnlyLabel(primary: false), side: side) ? side : nil
}
```
and in `actionButtonPadding` (2556-2558): `.modifier(DetailActionSquareLabel(side: primary ? nil : squareSide))`. The five `DetailActionSquareFrame(side: squareSide)` sites then get nil whenever the secondaries draw text. Add a third leg to `DetailActionSquareUITests`: `-detail_layout classic -debug.posterCornersOverride square` (Icons Only at its default, off) asserting `detail_action_watched`'s width is greater than its height + 20 and Play's width is unchanged from a Rounded launch within 2 pt; and a fourth with `-detail_action_icons_only YES` asserting Play's width is less than half the screen.

## P2

### P2-1. BUG-194: a `.hold` can swallow the last focus change for good, leaving the page un-anchored

`Screens/DetailView.swift:845-862`. On `.hold` the handler returns before everything below it: `focusMemory.clear()`, `userInteracted`, `awaitingHeroReturn = false`, `lastAnchored = nil`, the hero-return (`armHeroReturn`, 884-887) and the row anchor. Nothing replays the skipped change when the restore ends: the retire (2441-2445) and `.release` only call `endPopRestore()`, and the handler runs again only on the NEXT `focusedRow` change. Two reachable ways to end with focus on a held row and the page never corrected:
1. **The rungs never land.** The late rungs stand down after any viewer input (`hasInput(since: started)`, 2433), and a missing card (the cast list reloaded shorter, an index past the end) makes every rung a no-op. If the engine's stray landing on Play (row nil) was held, focus stays in the hero, the Cinematic page is never scrolled back to y = 0 and the dim stays on, until the viewer leaves the hero and comes back.
2. **The viewer moves inside the held row.** A press from Play to Trailer (still row nil) changes `heroFocus`, not `focusedRow`, so the gate never sees the input; the page stays where the hold left it after the retire.

`focusedRow` changing is the only trigger, so `.release` on viewer input works only when the viewer's first press also changes the row.

Fix: remember the swallowed change and replay it when the restore ends.
- New state beside `popFocusMoves` (in the `focusMemory` box, not `@State`, see P3-3): `heldFocusChange: (old: DetailRowID?, new: DetailRowID?)?`. In the `.hold` case, set it to `(old, row)` before `return` (keep the first `old`: `heldFocusChange = (heldFocusChange?.old ?? old, row)`).
- Move the body after the gate (from `// BUG-187: focus settled on a row…` to the end of the closure) into `private func handleFocusRowChange(old: DetailRowID?, new row: DetailRowID?)`, and call it from the closure.
- In `endPopRestore()`: `if let held = focusMemory.takeHeldFocusChange(), focusedRow == held.new { handleFocusRowChange(old: held.old, new: held.new) }` (only when focus is still where the held change put it; a later change already ran the handler itself).
- Release on viewer input that does not change the row: `.onReceive(NotificationCenter.default.publisher(for: ViewerInputClock.didRecord)) { _ in if popRestoreRow != nil { endPopRestore() } }` on the page (this also replays the held change through the line above).
- Unit test in `DetailFocusReturnTests`: none possible for the view, so add a probe token `held=<0|1>` to `debug_detail_focus` and extend `testBackFromCastMemberLandsInOneMove` to assert `held=0` three seconds after the pop.
