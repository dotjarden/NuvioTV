## P2 (should fix before merge)

### P2-1. Sync Line: nothing holds focus while the cues load (up to 12 s)

`Screens/Player/PlayerSubtitlesTab.swift:141-160`

`startSyncLine()` sets `syncSession`, so `body` swaps `tabBody` for `syncLineList`. That removes the focused "Sync Line" button. `syncFocus` is only assigned after the load ends (`focusAfterDelay(.cue(...))` or `.cancel`), which can take up to the 12 s timeout. Meanwhile the focus engine chooses where focus goes, and the likely candidate is the tab row above. The panel's tab row selects on focus (`PlayerTopPanelProbeTests` step 2: "selection follows focus"). If focus lands on a neighbouring tab, the Subtitles tab is torn down, the `@State` session is lost, and the cue list never appears. Even when focus lands on the Subtitles tab itself, a Down press during loading has no defined target.

Fix: give the list a focus target as soon as it appears, then move to the anchor when the cues arrive:

```swift
syncSession = SyncSession(capturedMs: captured, delayAtCaptureMs: delayAtCapture, cues: nil, failed: false)
focusAfterDelay(.cancel)          // the Cancel button exists as soon as the list does
Task { @MainActor in ... }         // unchanged: moves focus to .cue(anchor) or .cancel when done
```

Also add `.defaultFocus($syncFocus, .cancel)` on the list's `VStack` (tvOS 17+), so the engine's first pick is Cancel and not the tab row.

### P2-2. Sync Line decoding is weaker than the native subtitle path (UTF-16 files show "No subtitle lines found")

`Screens/Player/SyncLineCueLoader.swift:33-36`

`decode` tries UTF-8 and then ISO Latin-1. Latin-1 accepts any byte sequence, so a UTF-16 (BOM) SRT, which some add-on subtitle sources serve, "decodes" to garbage. The parser then finds no cues, and the list says "No subtitle lines found" while the same subtitle shows fine on screen. The app already has the right decoder: `SubtitleVTT.decode` (`Screens/SubtitleVTT.swift:432-444`) handles the UTF-16 LE/BE BOMs, then UTF-8, then Windows-1252, then Latin-1. The native fallback (`load(vtt: nil, fallbackURL:)`) also skips SDH stripping, so its list can show lines the screen never shows.

Fix: make `SubtitleVTT.decode` reachable (drop `private`, mark the helper `nonisolated`) and call it from `SyncLineCueLoader.decode`. For the native fallback, build the text with `SubtitleVTT.webVTT(from: data, stripSdh: <the server's stripSdh>)`, so the list matches what AVPlayer renders. Add `testDecodeUTF16LEWithBOM` to `SyncLineCueLoaderTests` (bytes `FF FE` + "1\n00:00:01,000 --> …" in UTF-16LE: 1 cue).

### P2-3. The new mpv UI legs skip the start gate the existing mpv leg needs

`iosApp/NuvioTVUITests/PlayerAudioSpeedUITests.swift:10-24`, `iosApp/NuvioTVUITests/SyncLineUITests.swift:20-38`

Both harnesses wait for `player.mpv` / `player.native`, then sleep a fixed 6 s or 8 s and press Down. The existing mpv leg they are modelled on (`NativePlayerParityUITests.testMpvPlaybackTabUnchanged`, `:108-129`) first waits for `debug_seekProbe` pos > 1, then for `debug_transportProbe` `vis=0` (the bar hidden). It has to: on mpv, `player.mpv` exists from the moment the controller loads (`MPVPlayerView.swift:564`), long before playback. A Down press while the transport bar is up, or before the panel recogniser is attached, does not open the panel. On a cold sim, 6 s is often not enough, so these legs will flake on their first run. The native legs are also gated on `PLAYER_BAR_PROBE`, while every existing native leg uses `PLAYER_NATIVE_PROBE` plus the `debug_nativeProbe` pos > 1 gate (`NativePlayerParityUITests.launchNative`, `:18-29`).

Fix: copy the start gates. For mpv, the seek-probe pos > 1 loop and the `vis == "0"` loop from `:117-129`. For native, `waitNative(app) { pos > 1 }` and `waitBarSettled`. The spec only asked for `PLAYER_BAR_PROBE`, so keep it for the mpv legs; for the native legs, either also require `PLAYER_NATIVE_PROBE` or note in the file header that they run under `PLAYER_BAR_PROBE`, so the gate invocation sets the right variables. The other UI-leg details (all P3): `SyncLineUITests.swift:84-85` presses Select the moment `cue.0` exists, but focus moves to the anchor 0.35 s later (add `pause(1)`). `PlayerAudioSpeedUITests.swift:15-17` passes `-player.nativeDolbyVision NO` and then `YES` for native (build the array once, like `SyncLineUITests` does).

### P2-4. Wave 3 retry gate drifts from the spec, and the "" case is untested

`Screens/NativePlaybackCoordinator.swift:1046-1048`, `iosApp/NuvioTVTests/PlayerEngineRouterTests.swift:83-88`

The spec is `attempt == 0 && !(supplementalCodecs ?? "").isEmpty`, with tests for nil and for "". The build uses `supplementalCodecs != nil`, and the test has no "" assertion. Today no producer emits "" (`RemuxSession.swift:1433-1453` emits nil or a formatted string). But `SegmentMap.swift:218` writes `SUPPLEMENTAL-CODECS=""` for an empty string, and the guard at `NativePlaybackCoordinator.swift:45` already treats "" as absent. So the two checks disagree about what "has a supplemental" means. P2 because the fix and the test land together with P1-1.

Fix: use the spec's form, and add `XCTAssertFalse(NativePlaybackCoordinator.signalingRetryAllowed(attempt: 0, supplementalCodecs: ""))`.

## P3 (nits and follow-ups)

### P3-1. Catalog key `"%@  %@"` comes from a Text interpolation that should not be localized

`Screens/Player/PlayerSubtitlesTab.swift:216`: `Text("\(Self.clock(cue.startTimeMs))  \(Self.firstLine(cue.text))")` is a `LocalizedStringKey` literal, so the compiler extracted `"%@  %@"` into `Localizable.xcstrings:76`. It is not user-facing copy: a timestamp and the add-on's own subtitle text, with nothing to translate. Fix: `Text(verbatim: "\(Self.clock(cue.startTimeMs))  \(Self.firstLine(cue.text))")`, then delete the `"%@  %@": {}` entry (Xcode would otherwise keep it as stale).

### P3-2. Catalog key `"on"` comes from the Remember row's accessibility value, a test hook

`Screens/Player/PlayerPlaybackColumns.swift:52`: `.accessibilityValue(isOn ? "on" : "off")` resolves to the `LocalizedStringKey` overload. `"on"` is new and empty; `"off"` already exists and is translated (`"désactivé"`, `"aus"`, …). So in French, VoiceOver and XCUI would read "on" for one state and "désactivé" for the other, and a leg run under `-AppleLanguages` would break. The panel's own row uses `Text(verbatim:)` for exactly this (`PlayerTopPanel.swift:168`). Fix: `.accessibilityValue(Text(verbatim: isOn ? "on" : "off"))`, then delete the `"on": {}` entry. (`PlayerSpeedRow`'s `"selected"` at `:32` has the same pre-existing issue; leave it or fix it the same way.)

### P3-3. Translations outstanding

The 11 other new keys are `{}`: "+%lld dB", "Audio Mode", "Boost", "Dialogue", "Dialogue raises voices. Boost can distort loud scenes.", "Loading subtitle lines…", "Press while a line is spoken, then pick that line.", "Remember Speed for This Show", "Sync Line", plus "No subtitle lines found" and "Unable to load subtitle lines", which are pre-filled only partly (no `de`). This is the main session's populate-and-translate step per the spec. It is listed here so it is not forgotten before the merge.

### P3-4. `SyncLineCueLoader` runs on the main actor

The target uses `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, so `enum SyncLineCueLoader` (`SyncLineCueLoader.swift:6`) is main-actor isolated. The file read, the decode and the Kotlin `PlayerSubtitleCueParser.parse` (regex over a whole feature-length SRT) all run on main, while the panel shows its spinner. Fix: mark the enum `nonisolated`. `URLSession` and `FileManager` are thread-safe, and `PlayerSubtitleCueParser` is a stateless Kotlin object.

### P3-5. A failed `af` set is remembered as applied

`Screens/MPVPlayerView.swift:2045-2046`: `lastAppliedAf = value` runs before `mpv_set_property_string`. If the set fails (rc < 0), the gate stops every later AUDIO_RECONFIG from retrying, and the log only shows the rc once. Fix: set `lastAppliedAf` only when `rc >= 0`. Also add to the device pass: switch audio tracks 5.1 to stereo with Dialogue on, and confirm the next AUDIO_RECONFIG swaps `pan` for `equalizer` with audio still playing (critique Risk 3).

### P3-6. Audio Delay "Reset" with a stream hint zeroes the hint for the session

`Screens/Player/MPVPlaybackTab.swift:97` → `setAudioDelay(0)` → `applyUserTotal(total 0)` → `sessionAdjust = −stream`. With a 2 s add-on hint, Reset gives 0 s, not the add-on's 2 s. D8 does not say which is intended. If Reset should mean "undo my tweak", have `setAudioDelay` treat Reset as `sessionAdjustMs = 0` while a hint is active (for example a `resetAudioDelay` closure that rebuilds the parts with session 0). If 0 is intended, say so in the release notes. Christian's call.

### P3-7. Native: a panel open can overwrite the saved speed with 1.0

`Screens/NativePlayerScreen.swift:590-592`: `speedModel.rate = Double(host.playerVC.selectedSpeed?.rate ?? 1)`, then `saveIfRemembered(rate:)`. If `selectedSpeed` is nil (the early `selectSpeed` before the view is in a window did not stick, which is critique Risk 13 and untested on hardware), the first panel open saves 1.0 over the remembered 1.25. Fix: save only when `selectedSpeed != nil`:

```swift
if let selected = host.playerVC.selectedSpeed { speedModel.saveIfRemembered(rate: Double(selected.rate)) }
```

`dismantleUIViewController` (`:618-625`) already prefers `selectedSpeed`, but falls back to `speedModel.rate`, which is fine.

### P3-8. Sync Line: a stale load can write into a newer session

`PlayerSubtitlesTab.swift:147`: `guard syncSession != nil` does not check that it is the same session. Cancel, then Sync Line again within the load time, and the first task fills the second session and moves focus using the first capture's anchor. The cues are the same file, so the effect is a wrong initial focus row. Fix: add `let id = UUID()` to `SyncSession` and guard on `syncSession?.id == id`.

### P3-9. Boost row may not fit the 520 pt Audio column

`Screens/Player/PlayerAudioTab.swift:74-92`: a 140 pt label, a `−` button, a 100 pt value, a `+` button and "Reset" (German "Zurücksetzen"), spaced by `Theme.Spacing.sm`, inside `.frame(width: 520)`. This probably fits in English, but check it with a sim screenshot in English and German. If it clips, shrink the label to 110 pt or drop the spacing to `xs`.

### P3-10. `rememberSpeedAvailable` is read once when the Playback tab opens

`MPVPlaybackTab.swift` `MPVPlaybackTabValues.init`. If the panel opens before FILE_LOADED (a slow start), the Remember row is missing until the panel reopens. Low impact. Fix if cheap: make it `@Published` on the state and mirror it like `rememberSpeed`.

### P3-11. Speed memory is keyed on `season != nil`

Both engines gate on `context.season != nil` (`MPVPlayerView.swift:1397`, `NativePlayerScreen.swift:116`), as the spec says. Check that anime contexts (Kitsu ids with an episode but no season) carry a season. If they do not, anime never shows the row. ## Checked and fine

- **Threading.** `applyAudioFilter` runs only on `eventQueue` (from `setAudioMode` via `eventQueue.async`, and from `drainEvents` on AUDIO_RECONFIG). It touches only mpv plus the `eventQueue`-only `lastAppliedAf`, and reads the mode from `UserDefaults`, not from main-actor state. `setAudioBoost` / `setAudioDelay` / `setRememberSpeed` / `onFileLoaded` run on main (`onFileLoaded` runs inside the FILE_LOADED `DispatchQueue.main.async`), and `audioDelayParts` is touched only there. `captureSyncPositionMs` reads `cachedProps()` under `propLock`, which is safe on main. The same-string gate stops an AUDIO_RECONFIG loop. `af` is untouched while Off: "" equals the initial `lastAppliedAf`, and the app sets no other `af` (no `spdif`, no other `volume` or `af` writers).
- **Swift isolation.** `signalingRetryAllowed` is `nonisolated static`, which suits the MainActor-default target. `dismantleUIViewController`'s `MainActor.assumeIsolated` is redundant (the representable protocol is `@MainActor`) but harmless, and it never traps because SwiftUI dismantles on main.
- **Retain cycles.** Every new closure stored on `MPVPlaybackState`, `PlayerTopPanelModel` or `NativeSpeedModel` captures the controller, state, adapter, host or speed model weakly (`MPVPlayerView.swift:553-556`, `MPVPlayerPanelAdapter.swift:37-41, 89-100`, `NativePlayerPanelAdapter.swift:38-39`, `NativePlayerScreen.swift:548-569`). `host.onOpenPanel` holds `speedModel` strongly, as before, and the speed model's closures hold the host weakly, so there is no cycle.
- **Maths.** `SubtitleSyncLine` matches Spec A and its tests (`delay = captured − cue − 300`, clamped ±60 s; the window uses the shown time `captured − delay`, `[−30 s, +10 s]`, last 30; the anchor rule). The sign agrees with mpv `sub-delay` and `SubtitleVTT.shift` (positive = later). Native snaps to 100 ms through `setSubtitleDelay(ms:)`, and the native leg expects the snap. `PlayerAudioEffects`: `clampBoost` snaps down to even steps, 10 dB = 316.2 % ≤ `volume-max` 320, and the pan map keeps c0…cN−1 with only c2 scaled; the 5.1 / 5.1(side) / 7.1 orders put FC at c2.
- **D8 precedence** (`StreamAudioDelay` + `MPVPlayerView.swift:1376-1390, 2003-2013`). With a hint, the total is the hint plus the session tweak, clamped ±60 s; the saved value is ignored and nothing is saved; a tweak changes only the session. Without a hint, the saved value is clamped ±10 s and persisted per episode, as before. Load applies without saving. The ±60 s row limit follows the hint (`audioDelayLimitSec`, mirrored and de-duplicated in `MPVPlaybackTabValues`). A new stream drops the tweak, because there is one `loadfile` per controller (`MPVPlayerView.swift:304`). The hint is copied in all three `PlaybackContext` builders, and the parse clamps ±60 s and accepts numbers and numeric strings (tested).
- **Speed memory.** mpv: load in `onFileLoaded` (series only), save in `setSpeed` only while Remember is on, scan writes bypass `setSpeed`, and off clears. Native: applied in `makeUIViewController` before `play()` (one AVPlayer per container; the signaling retry reuses it), saved on select, on panel open and on dismantle. The key `playback_speed|` is registered in `AccountDataStores`, and the storage is device-local per profile on all three actuals.
- **Spec conformance.** All panel ids match Spec A/B: `player.panel.syncLine`, `.syncLine.cancel`, `.syncLine.cue.N`, `player.panel.audioFx.boost.{minus,value,plus,reset}`, `player.panel.audioFx.mode.{off,dialogue}`, `player.panel.speed.remember`. No new id uses the `player.panel.audio.` prefix, so `PlayerTopPanelProbeTests`' audio-row count is unaffected (and it runs on native, where the rows are hidden). No `SettingsDescriptionID` was added (Q2). Audio Mode is Off/Dialogue only (Q1). The failure copy is "Unable to load subtitle lines", Spec A's composeApp-backed string, which replaces the plan's "Cues unavailable" (plan line 197). Release notes and the tester DM should use the new wording. The native rows stay hidden: `audioEffects` stays nil, and the old caption still shows there.
- **Regressions.** The existing Subtitles rows, the delay row and its ids are unchanged; the Sync Line row sits below the delay row, inside the same `supportsSubtitleDelay` block, so `SubtitleDelayProbeTests`' two Downs still land. The native Timing gate (`canRetime`) is unchanged, and `syncLineAvailable` mirrors it, including through the refetch hop. `walkAndPublishTracks` publishes the external source with the same equality gate as the track lists, and both a user pick (`selectSubtitle` → `refreshTracksAsync`) and the panel open (`activatePill` → `refreshTracksAsync`) re-walk, so the row follows the selection. The smoke harness defaults are unchanged with no knobs set (movie, `smoke-mpv`, no subtitles, no hint), so `testNativePlaybackTabSpeed`'s "1× ticked" holds. `LocalHLSServer.cachedBaseVTT` is lock-guarded and adds nothing else.
- **Kotlin.** `:shared:jvmTest :shared:tvosSimulatorArm64Test :composeApp:iosSimulatorArm64Test` passed in `gate-w1-kotlin.log` (BUILD SUCCESSFUL). The test names have no commas. `SubtitleSyncLineTest`, `StreamAudioDelayTest`, `PlaybackSpeedMemoryTest` and `StreamAudioDelayHintParseTest` cover every case the spec listed. The Swift fixtures that build `StreamBehaviorHints` were updated for the new parameter.
